# React

Use typed icon components with size and color props, CSS classes, and standard React SVG props.

## Installation

Install the package in a project with React 18.2+ or React 19:

```sh
npm install fyicons
```

Import an icon by name:

<LightButtonExample />

```tsx
import { IconSun } from 'fyicons';

export function LightButton() {
  return (
    <button type="button" aria-label="Switch to light mode">
      <IconSun size={24} color="#2563eb" />
    </button>
  );
}
```

The package uses ESM and supports tree shaking, so a compatible bundler removes unused icons. Direct imports are also available:

```tsx
import IconSun from 'fyicons/icons/IconSun';
```

For editable component source, follow the [shadcn instructions](/docs/getting-started/#editable-source-with-shadcn). Those components accept the same props.

<Callout aria-label="Next.js and Server Components">

**Next.js and Server Components**

Icons from `fyicons` and `fyicons/icons/*` work in Server Components without a `use client` directive. A Server Component can also render `FyiProvider` and pass it serializable defaults. For event handlers or refs, place the icon inside your own Client Component.

</Callout>

## Usage

### Size

Use `size` to set both dimensions. The original 16×16 viewBox stays the same when the icon scales.

<SizeExamples />

```tsx
<IconSun size={24} />
```

Set `size="1em"` to match the surrounding font size. Use `inline-block`, `inline-flex`, or `inline-grid` to keep the SVG in the text flow.

<InlineSizeExample />

```tsx
<span className="text-xl">
  Good morning <IconSun size="1em" className="inline-block" />
</span>
```

### Color

Use `color` to set an individual icon's color. Leave it unset to inherit the surrounding text color through `currentColor`.

<ColorExamples />

```tsx
<IconSun color="#2563eb" />
```

Or use a `className`; it will be added after the default classes:

<ClassNameExample />

```tsx
<IconSun className="text-blue-500" />
// Renders class="fy-icon fy-sun text-blue-500"
```

See [Styling](/docs/styling/) for CSS examples. CSS `color` rules and inline styles can override the `color` prop, which is an SVG presentation attribute.

<h3 id="shared-defaults">Provider</h3>

In FYIcons 0.3.0 and later, `FyiProvider` lets a group of icons share `size`, `color`, `className`, or `style`. Import the provider and its icons from `fyicons/client`.

<ProviderExample />

```tsx
import { FyiProvider, IconBookmark, IconFolder } from 'fyicons/client';

export function FileNavigation() {
  return (
    <FyiProvider size={20} className="nav-icon" color="red">
      <nav aria-label="Files">
        <a href="/files">
          <IconFolder /> All files
        </a>
        <a href="/saved">
          <IconBookmark size={16} /> Saved files
        </a>
      </nav>
    </FyiProvider>
  );
}
```

- Both icons get the `nav-icon` class,
- the folder inherits the 20px size,
- and the bookmark uses its own 16px size.

A nested provider can override defaults for a smaller group. Classes accumulate, and style properties merge from the outer provider to the inner provider to the icon, with the last value winning for each property.

Only icons imported from `fyicons/client` read these defaults. Use individual props or CSS for icons from `fyicons`, direct icon imports, and shadcn source icons.

## Using states & variants

While the library primarily includes outline-style icons, a good number of them have filled or otherwise stateful variants where it makes sense. Instead of having to hack your own version, just find and use the corresponding variant instead.

#### Booleans

Icons with logical boolean use cases, like hearts and stars, have both outline and filled variants so you can swap between them when toggling. A few examples:

<ToggleStateExample />

```tsx
'use client';

import { useState } from 'react';
import { IconHeart, IconHeartFill } from 'fyicons';

export function LikeButton() {
  const [liked, setLiked] = useState(false);

  return (
    <button type="button" aria-pressed={liked} onClick={() => setLiked(!liked)}>
      {liked ? <IconHeartFill className="text-red-400" /> : <IconHeart />}
      Like
    </button>
  );
}
```

Media playback icons also have alternates for commonly-toggled actions:

<MediaStateExample />

#### Meters and progress

A few icon families represent levels or stages: `Battery`, `Signal`, `Gauge`, `Meter`, and `ProgressTask`.

If you find you're missing a step, families with fewer variants can reuse a state across multiple steps, or you can request an additional step by opening an issue. Choose thresholds that fit what your application represents:

<LevelStateExample />

```tsx
const progressIcons = [
  IconProgressTaskTodo,
  IconProgressTask25,
  IconProgressTask50,
  IconProgressTask75,
  IconProgressTaskDone,
];

// level ranges from 0 to 100.
const Progress = progressIcons[Math.floor(level / 25)];

<Progress aria-label={`Progress: ${level}%`} />;
```

#### Loading indicators

The library currently includes `Loader`, `Spinner`, and `Rays`, which can be combined with keyframe animations for indeterminate or loading states. Unlike other icons, the former two are duotone with additional paths at lower opacities, so you get the full effect:

<LoadingExamples />

```tsx
import { IconSpinner, IconLoader, IconRays } from 'fyicons';

<IconSpinner
  aria-label="Loading"
  className="animate-spin [animation-timing-function:steps(10)] motion-reduce:animate-none"
/>;
<IconLoader
  aria-label="Loading"
  className="animate-spin motion-reduce:animate-none"
/>;
<IconRays
  aria-label="Loading"
  className="animate-spin motion-reduce:animate-none"
/>;
```

<h2 id="props">API</h2>

All props are optional. Components also accept standard React SVG props and event handlers. Many icons use filled paths, so `strokeWidth` does not change their visual weight.

| Prop              | Type                           | Description                                                                      |
| ----------------- | ------------------------------ | -------------------------------------------------------------------------------- |
| `size`            | `number \| string`             | Sets width and height. Accepts a number or CSS length string; defaults to `16`.  |
| `width`, `height` | `number \| string`             | Override the corresponding dimension from `size`.                                |
| `color`           | `string`                       | Sets the SVG color used by `currentColor`. Inherits the text color when omitted. |
| `className`       | `string`                       | Adds your classes after `fy-icon` and `fy-{icon-name}`.                          |
| `style`           | `React.CSSProperties`          | Applies inline CSS styles.                                                       |
| `title`           | `string`                       | Adds an SVG title. Does not change the decorative accessibility default.         |
| `aria-label`      | `string`                       | Names the icon and sets `role="img"` by default.                                 |
| `aria-labelledby` | `string`                       | References an external label. Also set `role="img"` and `aria-hidden={false}`.   |
| `role`            | `React.AriaRole`               | Overrides the icon's ARIA role.                                                  |
| `aria-hidden`     | `boolean \| "true" \| "false"` | Overrides whether the icon is hidden from assistive technology.                  |
| `ref`             | `React.Ref<SVGSVGElement>`     | Gives access to the SVG element.                                                 |

<h2 id="accessibility">Accessibility</h2>

For non-decorative standalone icons, be sure to name the information or action that the icon represents. Based on your use case, you can take one of several different approaches:

<DocsAccordion labelledBy="accessibility">

<DocsAccordionItem title="Decorative icons" value="decorative-icons">

Icons without an `aria-label` prop (or non-empty string) are given `aria-hidden="true"` by default. Leave this default when nearby text already explains the icon:

<DecorativeIconExample />

```tsx
<span>
  <IconSun /> Light mode
</span>
```

If the text is conditionally rendered (for example, hiding a label on mobile), prefer to visually hide the text instead of using `display: none`, so it remains available to screen readers.

</DocsAccordionItem>

<DocsAccordionItem title="Standalone or illustrative icons" value="standalone-icons">

Add `aria-label` when the icon communicates information on its own, such as when it illustrates a concept not represented by surrounding text. Often, an icon will stand in for a status:

<StandaloneIconExample />

```tsx
<IconGitMerge aria-label="Status: Merged" />
```

In this case, the component sets `role="img"` and the `aria-label` is announced to screen readers. This is akin to setting `alt` on an `<img>` element.

</DocsAccordionItem>

<DocsAccordionItem title="Icon buttons" value="icon-buttons">

For icon-only actions without a visible label, provide the accessible name on the parent and leave the icon decorative. This gives the control a single accessible name:

<IconButtonExample />

```tsx
<button type="button" aria-label="Switch to light mode">
  <IconSun />
</button>
```

You wouldn't set `aria-label` in this case, as it would read twice.

</DocsAccordionItem>

<DocsAccordionItem title="External labels and titles" value="external-labels-and-titles">

A `title` or `aria-labelledby` alone does not change the decorative default. For an external label, set all three props:

<ExternalLabelExample />

```tsx
<span id="light-mode-label">Light mode</span>
<IconSun
  aria-labelledby="light-mode-label"
  role="img"
  aria-hidden={false}
/>
```

Explicit `role` and `aria-hidden` props override the defaults. Empty or whitespace-only labels remain decorative.

</DocsAccordionItem>

</DocsAccordion>
